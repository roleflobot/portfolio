# Engineering Notes — 고객 VOC 분석 Agent

이 문서는 이 프로젝트를 어떤 방식으로 설계·구현·검증했는지, 그리고 개발 과정에서 실제로 마주친
엔지니어링 이슈를 어떻게 진단하고 해결했는지 정리한 기록입니다.

## 개발 방식

이 프로젝트는 Claude Code와 n8n MCP(Model Context Protocol)를 활용한 AI-assisted 엔지니어링으로
개발했습니다.

제가 직접 수행한 부분:
- 요구사항 정의 및 워크플로우 아키텍처 설계 (Google Form → Sheets → n8n → Gemini → Discord)
- 중복 문의 판정 로직 설계 (물품번호 + 정규화된 문의내용 조합 키)
- LLM 출력 계약(JSON 스키마)과 계약 위반 시 fallback 정책 설계
- 엣지 케이스 테스트 시나리오 설계 및 Pin Data 기반 fault injection 테스트
- 다중 아이템 동시 처리 시 발생한 데이터 유실 버그의 원인 진단
- 실제 운영 환경(Form 제출 → Gemini 분류 → Sheet 저장 → Discord 발송) 통합 검증
- 최종 승인 및 배포 판단

Claude Code는 n8n 워크플로우를 프로그램적으로 조회·수정하는 구현 및 디버깅 보조 도구로
사용했습니다. 워크플로우 구조를 코드로 직접 다룰 수 있었기 때문에, 노드 하나하나를 UI로
클릭하는 대신 문제를 원인 단위로 진단하고 재현 테스트까지 빠르게 반복할 수 있었습니다.

## 핵심 엔지니어링 이슈 — 다중 아이템 동시 유입 시 데이터 유실

### 문제 발견
테스트 중, 트리거가 신규 문의를 **한 번에 2건 이상** 감지하는 상황에서 일부 문의가 워크플로우
중간에 사라지는 현상을 발견했습니다. 신규 문의가 한 건씩만 들어올 때는 전혀 드러나지 않는
유형의 버그였습니다.

### 원인 진단
Google Sheets의 "Get row(s)"(중복 조회) 노드가 여러 입력 아이템을 한꺼번에 받았을 때,
**아이템별로 독립 실행되지 않고 첫 번째 아이템의 조건으로 단 한 번만 실행**된다는 사실을
실제 실행 데이터로 확인했습니다. 그 결과 두 번째 이후 문의는 조회 결과 자체가 없어
"중복"으로 잘못 판정되어 워크플로우에서 조용히 탈락했습니다.

### 해결
- 정규화 단계와 중복 조회 단계 사이에 아이템을 1개씩 순차 처리하는 루프를 삽입해,
  트리거가 여러 건을 동시에 감지하더라도 파이프라인은 항상 한 번에 한 건씩 처리하도록 강제
- 워크플로우의 모든 종료 분기(중복 차단/정상 발송)를 루프로 다시 연결해 한 아이템 처리가
  끝나면 다음 아이템으로 자동으로 넘어가도록 구성

### 검증
- 신규 문의 2건을 동시에 주입하는 재현 테스트를 실행해, 두 건 모두 조회 → 중복판정 →
  LLM 분류 → 저장 단계까지 각각 독립적으로 완주함을 실행 데이터로 확인
- Pin Data 기반의 결정론적 로직 테스트(중복 판정 조합, LLM 출력 계약 위반 케이스)와,
  실제 Google Form 제출 → 실제 Gemini 호출 → 실제 Sheet 저장 → 실제 Discord 발송까지
  이어지는 실제 운영 환경 테스트를 모두 별도로 수행해 두 가지를 서로 다른 층위에서 검증
  (Pin Data 테스트만으로는 실제 서비스 연동까지는 검증되지 않는다는 점을 인지하고
  의도적으로 이중으로 확인했습니다)

## 설계 결정 — "LLM은 판단, 코드는 검증"

LLM 구조화 출력(JSON)에 스키마를 걸어도 모델이 계약을 어길 가능성은 항상 남아 있습니다.
그래서 이 프로젝트는 다음 원칙을 일관되게 적용했습니다.

- 분류·감정·긴급도·요약 등 **판단이 필요한 부분은 LLM에 맡긴다**
- 그 출력이 정해진 형식(필수 필드, 허용값, 타입)을 지키는지는 **코드가 항상 검증한다**
- 검증에 실패하면 워크플로우를 중단시키는 대신, 안전한 기본값으로 보정하고 `needs_review`
  플래그를 남겨 후속 확인이 가능하도록 설계

이 안전판은 필드 누락, 허용값 밖의 값, 타입 불일치, JSON이 아닌 응답 등 4가지 계약 위반
유형을 인위적으로 주입해(Pin Data fault injection) 각각 독립적으로 검증했습니다.

## 사용 기술
Google Forms, Google Sheets, n8n, Google Gemini API, Discord, Claude Code (n8n MCP)
